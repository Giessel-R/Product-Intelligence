Hallucination Prevention

Four overlapping layers that prevent the AI model from inventing capabilities, upgrading weak evidence, or making gap claims without a basis. Every AI call in the system is subject to at least one of these layers.

shield Why This Matters

Competitive intelligence is only useful if it's accurate. A false gap claim: "Okta has X, Ping doesn't": can influence real product decisions. The system is designed to abstain rather than speculate. When evidence is weak, the system returns not_enough_evidence: true and the record is dropped entirely.

layers Prevention Layers
1
Prompt Rules
Market Watch · IPS · CI
Six rules are included verbatim in every AI prompt in the system:
  1. Marketing language (seamless, AI-powered) is not evidence of a capability: ignore it
  2. GitHub code ≠ shipped feature: only README usage instructions, CHANGELOG entries, or official docs count
  3. Abstain by default: if evidence is weak, return not_enough_evidence: true
  4. observed_fact and analyst_interpretation are always separate fields
  5. No gap claims without reading internal_capability_map first
  6. Gap or requirement claims require confidence ≥ 4
2
Parser Safety Caps
IPS · Stage 2
Added in Stage 2. The Parse Capabilities Code node in Internal Product Specialist enforces hard limits on the model's output: regardless of what the model returned:
  • sample_app source type → hard cap at sample_only, confidence ≤ 3
  • github_repo → cannot return production_mature unless strong release/version signals are present
  • press_release → high-level signal only; no confidence boost beyond what versioned release evidence would support
When a parser cap fires, the maturity reason is tagged with [parser-cap].
3
Relevance Gate
Market Watch · Stage 4
Added in Stage 4. Before any AI call is made in Market Watch, a Code node scores the page for relevance. Pages that fail the gate never reach the model at all: saving cost and preventing low-signal content from being treated as evidence.

Gate formula: base_score(source_type) + title_matches×2 + body_matches×1 (body capped at 5). Pass condition: score ≥ 3 AND keywords_matched ≥ 1.
4
Review Flag
CI · Memory & Audit
Competitor Intelligence sets review_flag: TRUE on any finding where confidence is uncertain or parity claims require validation. Memory & Audit reads these flags weekly, summarizes the flagged findings, and writes a quality report to execution_log. Human review is always available for items the system is uncertain about.
info
Parser Cap Tag
When [parser-cap] appears in a maturity_reason field in Google Sheets, the parser overrode the model's output. The original value is not stored: only the capped value is written to the sheet.
