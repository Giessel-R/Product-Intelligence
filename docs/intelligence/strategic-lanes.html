Strategic Lanes

Every finding, capability, and structured analysis is classified into one of 6 strategic lanes. Lanes define the shared vocabulary across Market Watch, IPS, Competitor Intelligence, and the Newsletter.

The 6 lanes represent the strategic product areas that matter most to Ping Identity. Claude is instructed to use exactly these lane identifiers — no others. Competitor Intelligence groups evidence by lane before analysis, and the newsletter reports findings per lane.

IDENTITY_EXPERIENCE
Identity Experience
Login UX, hosted pages, branding, account flows, authentication journeys, end-user customization, white-labeling, MFA UX.
Example: "Okta redesigned their login widget with new customization options and hosted page templates"
DEVELOPER_PLATFORM
Developer Platform
SDKs, developer tools, documentation quality, DX, sample apps, onboarding speed, implementation guides, quickstarts.
Example: "Auth0 released a new JavaScript SDK with MFA built in and a 5-minute quickstart guide"
AI_AGENT_IDENTITY
AI Agent Identity
AI agent authorization, MCP protocol, A2A (agent-to-agent) patterns, non-human identity, machine-to-machine flows, workload identity.
Example: "Okta announced MCP Server support — authentication for AI agents hitting Okta-protected resources"
UI_ARCHITECTURE
UI Architecture
Design systems, composable UI, headless patterns, theming, accessibility standards, component libraries, customization APIs.
Example: "Auth0 released a component library for their hosted pages — headless, bring-your-own-CSS"
DESIGN_WORKFLOWS
Design Workflows
Figma tooling, design-to-code pipelines, mockup generators, design token systems, prototyping integration, handoff tools.
Example: "Okta published a Figma design system for identity UI components with token mapping"
STRATEGIC_SIGNALS
Strategic Signals
Pricing changes, product launches, acquisitions, partnerships, job postings, market positioning shifts, packaging changes.
Example: "Auth0 quietly changed their pricing page — free tier limits reduced from 7,500 to 5,000 MAUs"
info How Lanes Are Used

Every Claude call that produces evidence or findings must assign a lane. The lane is used to:

1
Classification (Market Watch)
Claude Haiku assigns a lane to each evidence record. Lane is stored in evidence_log.lane. The relevance gate uses source type, not lane, for pre-filtering.
2
Capability Grouping (IPS)
Internal Product Specialist organizes Ping's capability map by lane. The Aggregate Ping Capabilities node in CI restructures these into tiered objects per lane before analysis.
3
Gap Analysis (Competitor Intelligence)
CI compares competitor evidence per lane against Ping's per-lane capability tiers. The REASONING ORDER prompt instructs Claude to identify the lane first, then check Ping's tiers for that lane specifically.
