Evidence Scoring

Every finding is scored on two dimensions: importance (how relevant is this to Ping's business?) and confidence (how certain are we that this claim is correct?). Both are required. Both are used downstream.

warning_amber
Hard Rule: Confidence Threshold
Gap claims and competitive action recommendations require confidence ≥ 4. No exceptions. Low-confidence findings (1–3) are logged but never used to claim a gap or trigger a Draft Brief action without explicit human review.
priority_high Importance Score (1–5)

Assigned by Claude. Reflects how meaningful this change is for Ping Identity's product and business.

5
Core to Ping's business
Directly competitive in Ping's primary market. A feature Ping's customers actively use or compare against. This affects renewal conversations.
Example: Okta launches an MCP-native identity API that directly competes with PingGateway's MCP security layer
4
Significant feature in Ping's strategic area
Important for Ping's roadmap and competitive positioning, but not immediately at the core of existing deals.
Example: Auth0 ships a headless UI component library: directly relevant to Ping's UI Architecture lane
3
Relevant but secondary
Worth tracking. Could become important if a trend develops, but not immediately actionable.
Example: Okta improves their Figma design tokens documentation
2
Tangential or indirect
Adjacent to Ping's space but not a direct competitive concern. Logged for completeness.
Example: Auth0 launches a new blog series on identity best practices
1
Not applicable to Ping's world
Not relevant to Ping's competitive landscape. Record may be logged but will not surface in analysis or newsletter.
Example: Competitor updates their About Us page with new team photos
verified Confidence Score (1–5)

Assigned by Claude. Reflects how certain we are that the claim is accurate and correctly understood from the source.

5
Explicit GA announcement or official changelog
The source directly states a versioned release, general availability date, or official changelog entry. No inference required.
Example: "v3.2 released today with MCP support: see changelog at developer.okta.com/docs/release-notes"
4
Official blog or docs with code examples
Official blog post or documentation page clearly describing a feature, with code examples or implementation instructions.
Example: Auth0 blog post titled "Integrating MFA into your React app" with full code walkthrough
3
Referenced in docs or README with some detail
The feature is mentioned in documentation or a README with some supporting detail, but not a complete description.
Example: SDK README mentions "MCP support coming in v2.0" in a features table
2
Inferred from content structure change
A new navigation section appeared, or a page structure changed in a way that implies a new feature area: but no explicit description found.
Example: New "AI Identity" section appeared in the Okta docs navigation: no content yet
1
Marketing language only: record dropped
The source uses marketing terms like "seamless", "AI-powered", "intelligent" without describing an actual capability. Claude returns not_enough_evidence: true and the record is not logged.
Example: Homepage banner: "Our AI-powered identity platform keeps you secure seamlessly"
