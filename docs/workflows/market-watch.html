Market Watch

Visits every competitor URL in the config list, detects page changes via MD5 hashing, scores relevance, and asks Claude Haiku to classify findings into structured evidence records.

info How It Works

Market Watch is the system's eyes. It visits each competitor URL from the config tab every day, downloads the page content, and generates an MD5 hash. If the hash is different from the last recorded hash in change_snapshots, the page has changed.

Changed pages go through a Stage 4 relevance gate before reaching Claude. The gate scores each page against a keyword list and source-type base scores — only pages scoring ≥ 3 with at least 1 keyword match reach the Haiku classification step. Low-signal pages (blog posts about company culture, homepage CSS tweaks) are silently dropped before consuming any API budget.

For pages that pass the gate, Claude Haiku summarizes what changed, assigns a strategic lane, and scores importance and confidence. If Claude flags not_enough_evidence: true, the record is dropped. Otherwise, it's written to evidence_log and the snapshot is updated.

executeWorkflowTrigger

Set
Picks up the run_id from the orchestrator (or generates its own if run manually). Sets the current date and week — used to timestamp all records written during this run.
3
Read All Snapshots
Google Sheets
Reads the entire change_snapshots tab. This tab stores the last-known MD5 hash per competitor URL — the baseline for detecting changes. Each row: competitor_id, source_url, last_hash, last_checked.
4
Aggregate Snapshots
Code
Consolidates snapshot rows into a single lookup object keyed by URL → hash. Makes the comparison in the next steps fast: "what was this URL's hash last time?"
5
Read Competitor Config
Google Sheets
Reads the config tab — the list of competitors and URLs to monitor. Only rows with active = TRUE are used. Each row: competitor_id, source_type, url.
6
Build URL Queue
Code
Combines the competitor config with snapshot data to build the full list of URLs to check. Each item in the queue includes the competitor name, tier, source type, URL, and the previous hash to compare against.
7
Split to Individual URLs
Split Out
Takes the URL queue (one big list) and splits it into individual items so downstream nodes process one URL at a time.
8
Fetch and Hash Page
HTTP Request
For each URL: fetches the page, downloads the HTML content, generates an MD5 hash. Compares new hash against the previous hash from snapshots. If different and content length > 200 characters, marks as changed = true.
9
Has Page Changed?
IF
Decision node. TRUE (changed) → Score Relevance gate → possibly Build Haiku Prompt. FALSE (unchanged) → Update Snapshot (Unchanged) and stop processing this URL.
10
Score Relevance
Stage 4
Stage 4 node. Computes a relevance score for the changed page. Formula: base_score(source_type) + title_keyword_matches×2 + body_keyword_matches×1 (body capped at 5 matches). Base scores: changelog/release_notes/documentation = 3, developer_portal = 2, github/blog = 1, homepage = 0. GitHub repo-name check against curated list adds +2. Pass condition: score >= 3 AND keywords_matched >= 1.
11
Passes Relevance Gate?
Stage 4
Stage 4 IF node. Condition: relevance_pass === true. TRUE → Build Haiku Prompt (existing path). FALSE → Item dropped silently. Visible in n8n execution output as a terminated branch.
12
Build Haiku Prompt
Code
Constructs the Claude Haiku prompt with up to 3,000 characters of page content. Instructs Claude to summarize what changed, classify the strategic lane, and score importance (1–5) and confidence (1–5). Sets not_enough_evidence: true if the change is noise.
13
Summarize with Haiku
HTTP Request → Anthropic
Sends the prompt to Claude Haiku via the Anthropic API. Uses predefinedCredentialType: httpHeaderAuth with credential P6dgBaH33wjoGxqb. Returns structured JSON: summary, observed_fact, analyst_interpretation, lane, importance_score, confidence_score, evidence_strength, not_enough_evidence.
14
Parse AI and Build Record
Code
Parses Claude's JSON response. If not_enough_evidence: true, the record is dropped — nothing logged. Otherwise, builds a clean evidence record with a unique ID (EV-{competitor}-{timestamp}), all timestamps, and classification fields.
15
Write to evidence_log
Google Sheets
Appends the new evidence record to the evidence_log tab. This is the raw findings table — the source for all downstream Competitor Intelligence analysis. Status set to new.
16
Update Snapshot (Changed)
Google Sheets
Updates the change_snapshots tab with the new hash and last_changed timestamp. Next run, this new hash becomes the baseline. The parallel Update Snapshot (Unchanged) node does the same for pages that passed the hash check but didn't change — just updating last_checked.
