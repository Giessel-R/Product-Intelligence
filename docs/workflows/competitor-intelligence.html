Competitor Intelligence

Compares raw evidence from Market Watch against Ping's capability map to identify gaps, parity, and strategic signals. Uses maturity-tiered analysis to prevent both over-claiming and under-claiming competitive differences.

Workflow IDmY5wIkPWlolzcUbn
Triggered byMaster Orchestrator · Tuesdays and Thursdays
AI modelClaude Sonnet: maturity-aware gap analysis
Writes tostructured_findings (Google Sheets) · Notion Competitor Cards
Reads fromevidence_log · internal_capability_map
info How It Works

CI picks up raw evidence from Market Watch and turns it into structured competitive analysis. It reads new evidence from the last 3 days only, groups it by competitor, then reads Ping's tiered capability map. The grouping ensures Claude sees all of Okta's recent signals together: not one page change at a time.

Stage 3 upgraded the analysis prompts to use a tiered capability structure. Not just "Ping has MCP" but "Ping has MCP at documented level from developer_portal, with production_mature from release_notes for PingGateway." This precision prevents both over-claiming gaps (when Ping has the capability but at lower maturity) and dismissing real gaps (when Ping's evidence is weak).

The recommended action vocabulary is deliberately narrow: Watch | Validate | Draft Brief. No other values.

Google Sheets
Reads all rows from evidence_log.
4
Filter New Only
Code
Filters to rows with status = "new" AND date_found >= 3 days ago. Groups by competitor_id: all Okta findings bundled, all Auth0 findings bundled. If zero evidence remains after filtering, the workflow exits gracefully without errors.
5
Read Capability Map
Google Sheets
Reads internal_capability_map: the Monday-rebuilt map of Ping's capabilities. This must run before analysis.
6
Aggregate Ping Capabilities
Stage 3
Stage 3 node. Restructures flat capability rows into a tiered object per lane. For each of the 6 lanes: { production_mature: [...], documented: [...], partial: [...], unclear: [...], sample_only: [], no_evidence: bool, source_types_present: [] }. All 5 tiers always present: even if empty. unclear is its own bucket, never merged into partial. Source type is included in each capability entry for prompt context.
7
Build Analysis Prompts
Stage 3
Stage 3 node. Constructs the Sonnet analysis prompt with: TIER DEFINITIONS (explains all 5 maturity tiers + no_evidence to Claude), REASONING ORDER (6 steps: identify lane → state competitor evidence → check Ping tiers → compare → note press_release → set action), CLAIM VOCABULARY (anchored phrases for all tier combinations), CONFIDENCE BEHAVIOR (unclear/weak Ping → reduce confidence; press_release alone → no confidence raise), SOURCE TYPE CALIBRATION.
8
Analyze with Sonnet
HTTP Request → Anthropic
Sends the analysis prompt to Claude Sonnet. Returns structured JSON: gap_vs_ping, parity_vs_ping, ping_advantage, observed_facts, analyst_interpretation, recommended_action (Watch|Validate|Draft Brief), confidence_score, review_flag.
9
Parse and Build Finding
Code
Parses Claude's response and assigns a unique finding ID: SF-{competitor}-{timestamp}. Validates recommended_action is one of the 3 allowed values.
10
Write to structured_findings
Google Sheets
Appends the structured finding to structured_findings. This is the processed intelligence layer: cleaner and more actionable than raw evidence_log.
11
Mark Evidence Processed
Google Sheets
Updates evidence_log rows for all evidence used in this run: sets status = "processed". Prevents the same evidence from being analyzed again in the next CI run.
12
Update Notion Competitor Card
HTTP Request → Notion API
POSTs a new page to the Notion Competitor Cards database (ID: YOUR_NOTION_COMPETITOR_DB_ID). Uses predefinedCredentialType: notionApi with credential YOUR_NOTION_CREDENTIAL_ID. Direct HTTP Request: not the n8n Notion node (which has a rich_text bug in v2.2).
warning_amber
Evidence Cutoff: 3 Days
CI reads only evidence from the last 3 days. Evidence older than 3 days is not included in analysis, even if status = "new". Gaps in the schedule mean that evidence from missed days may never be analyzed.
info
Notion Node v2.2 Bug
The n8n Notion node v2.2 has a known rich_text bug: property values are silently sent as blank. This workflow uses a direct HTTP Request to the Notion API at https://api.notion.com/v1/pages instead of the n8n node. Use predefinedCredentialType: notionApi.
