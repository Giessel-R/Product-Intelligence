Error Handler

Catches every crash across all workflows. Logs it to Google Sheets. Emails you immediately for critical failures. Runs automatically: you never trigger it manually.

info How It Works

Every workflow in the system has its n8n Error Trigger set to route to this workflow. When any workflow throws an unhandled error, n8n automatically sends the error data here. The Error Handler never needs to be manually triggered: it's always listening.

Failures are classified as critical or non-critical. Critical failures are those in the Master Orchestrator, Newsletter, or Error Handler itself: workflows that, if they fail, break the entire pipeline or leave you blind to other failures. Non-critical failures include individual URL scrape failures, one bad competitor page, or a single CI parsing error: the system can recover from these on the next run.

All failures are logged. Only critical failures send a push notification via ntfy.sh to channel YOUR_NTFY_TOPIC. ntfy.sh was chosen over Gmail because Gmail OAuth can expire: if Gmail is down, it can't alert you that Gmail is down. ntfy.sh has no OAuth dependency.

account_tree Node Breakdown
1
Error Trigger
errorTrigger
The entry point. n8n automatically fires this node whenever any workflow in the system throws an unhandled error. Receives: the name of the workflow that failed, the node where the failure occurred, the error message, and the run ID.
2
Build Error Record
Code
Takes the raw error data and formats it into a structured record. Assigns a unique error ID. Timestamps the failure. Determines severity: critical if the failed workflow is the Orchestrator, Newsletter, or Error Handler itself: non-critical for everything else. Structures all fields for error_log.
3
Log to error_log
Google Sheets
Writes the formatted error record to the error_log tab in Google Sheets. This is the permanent audit trail of every failure. Fields: id, timestamp, run_id, workflow_name, node_name, error_message, severity, resolved.
4
Is Critical?
IF
Checks the severity field from the error record. TRUE (critical) → Send ntfy Alert. FALSE (non-critical) → Stop here. Non-critical failures are logged but do not generate a push alert.
5
Send ntfy Alert
HTTP Request → ntfy.sh
Sends a push notification to https://ntfy.sh/YOUR_NTFY_TOPIC for critical failures. Title: PI System Alert: [Workflow Name] failed. Body includes: workflow name, failed node name, error message, run ID, timestamp. Uses an HTTP Request node (no OAuth: ntfy.sh is credential-free for public topics).
info
Error Handler Scope
To add a new workflow to the error routing system: in the n8n workflow settings for the new workflow, set the Error Trigger to point to PI: Error Handler. No changes to the Error Handler workflow itself are needed.
