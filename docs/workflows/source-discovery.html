Source Discovery

Crawls Ping Identity's seed documentation pages monthly, extracts and classifies every internal link, and writes newly discovered URLs to the source_registry as candidates: automatically expanding the IPS source list without manual curation.

ScheduleFirst Monday of each month · 6:30 AM ET (also manually triggerable)
AI modelClaude Haiku: used only for ambiguous URLs (~$0.001/call)
Reads fromsource_registry (seed sources with source_role = family_index)
Writes tosource_registry (new candidate rows · safe metadata updates)
info How It Works

Source Discovery is the system's self-expanding index. Instead of manually adding URLs to the source_registry, this workflow reads every family_index seed from Sheets, fetches each page via the Jina reader API (which returns clean markdown), and parses every internal link found on the page.

Each discovered link goes through a two-pass classification pipeline. First, a set of deterministic path rules assigns a source_role (e.g. release_notes, platform_specific, api_reference) based on URL patterns. Links that don't match any rule are flagged as unknown and forwarded to Claude Haiku for a second-pass classification using anchor text and seed context.

After classification, the workflow reads the current source_registry and deduplicates. New URLs are appended as status = candidate rows: they don't become active sources until a human promotes them. URLs already in the registry have only their last_seen and last_checked timestamps updated (no other fields are touched).

info
Stage 5: Hybrid Discovery Model
This workflow is the core of Stage 5. It replaces manual source curation with a monthly automated crawl. IPS reads active sources; Discovery writes candidate sources. A human review step sits between them: candidates are never activated automatically.
account_tree Node Breakdown
1
Monthly Schedule
Schedule Trigger
Fires on the first Monday of each month at 6:30 AM ET using the cron expression 30 6 1-7 * 1. Designed to run independently of the daily Master Orchestrator: it's a long-running crawl that shouldn't block the daily pipeline.
1b
Manual Trigger
Manual Trigger
Allows the workflow to be triggered on-demand from the n8n UI. Useful for initial validation and one-off re-crawls without waiting for the monthly schedule.
2
Discovery Config
Code
Emits a single config item with two runtime flags: USE_CLAUDE_CLASSIFICATION (toggle Claude off entirely for dry runs) and MAX_CLAUDE_CANDIDATES_PER_RUN (cap on items sent to Claude: default 200). Both values are read by downstream nodes.
3
Read Seed Sources
Google Sheets
Reads the entire source_registry tab. All filtering happens in the next node: this reads the full range A:Z to ensure no columns are missed.
4
Filter Seeds
Code
Keeps only rows where source_role = family_index, status is active or discovery_only, and source_type ≠ github_repo (GitHub repos are excluded: their link structure is nav menus, not doc pages). These are the crawl seeds.
5
Prepare Seed Fetch
Code
Normalizes each seed URL and prepends the Jina reader prefix: https://r.jina.ai/{url}. Jina fetches the page and returns clean markdown: stripping nav, scripts, and ads so link extraction is reliable.
6
Fetch Seed Page
HTTP Request
Fetches each seed page via Jina with a 20-second timeout. onError: continueRegularOutput ensures that a single failed fetch doesn't stop the run: it passes through an error flag that the next node checks.
7
Skip If Fetch Failed
Code
Drops any fetch results that returned an error or returned fewer than 100 characters of content. Zips fetch results back to their original seed data (to carry forward source_id, capability_area, product_name).
8
Extract Links
Code
Parses the Jina markdown for all [text](url) link patterns. Filters to same-hostname links only. Applies a deny list (/search, /login, /tag/, pagination paths, etc.). For seeds in a subsection (path depth ≥ 2), enforces a section boundary: links outside the seed's directory are hard-rejected. Root-level seeds are intentionally broad. Deduplicates by normalized URL within each seed.
9
Normalize URLs
Code
Strips URL fragments (#section), removes tracking parameters (utm_*, ref, source, campaign), lowercases the hostname, and removes trailing slashes. Produces a stable normalized_url used as the deduplication key throughout the rest of the workflow.
10
Reclassify & Filter
Stage 5
Applies the path rule set before classification. Hard rejects: links at path depth ≤ 1 (root-level pages), cross-product directories (/pingam/, /pingfederate/, /solution-guides/), and non-MCP AIC sections. Also reclassifies SDK changelog and release-notes paths to the correct product_name and capability_area regardless of which seed they came from.
11
Classify Links
Stage 5
Rules-based source_role assignment. Patterns checked in order: release_notes (changelog/whatsnew paths) → api_reference (api/ paths) → family_index (index.html) → sample_only (samples/ paths) → platform_specific (android/ios/swift paths) → use_case (guide/how-to paths) → unknown (no match). Sets suggested_priority (P1/P2/P3) and flags is_authoritative_classification for items where the rules are definitive.
12
Build Claude Prompt
Stage 5
Prepares each item for the Claude branch. Only items with source_role = unknown are candidates for Claude enrichment. Applies the MAX_CLAUDE_CANDIDATES_PER_RUN cap: items beyond the cap are marked _skip_claude: true and routed around Claude with their rules classification kept. Confidently-classified items always skip Claude.
13
Needs Claude?
IF
Routes items: TRUE (_skip_claude = false) → Format Claude Prompt → Call Claude Haiku → Parse & Merge. FALSE → Rejoin Classification Paths directly, keeping their rules-based classification.
14
Format Claude Prompt
Code
Builds a structured prompt per candidate using: seed page URL, product name, seed page title, candidate URL, and anchor text. Asks Claude to return source_role, capability_tag (from a curated list of ~32 tags), and confidence (1–5). If Claude can't classify with confidence ≥ 3, it returns not_enough_context: true.
15
Call Claude Haiku
HTTP Request → Anthropic
Calls Claude Haiku with a 256-token budget: classification returns are always short. Uses predefinedCredentialType: httpHeaderAuth with credential YOUR_ANTHROPIC_CREDENTIAL_ID and the required anthropic-version: 2023-06-01 header. onError: continueRegularOutput prevents API failures from breaking the run.
16
Parse and Merge Classification
Code
Merges Claude's classification with the rules output. Merge logic: if Claude agrees with the rules-assigned role → claude_assisted. If Claude disagrees and confidence ≥ 4 (≥ 5 for authoritative-classified items) → claude_override. Otherwise the rules-based role is kept. If Claude returned not_enough_context or failed → fall back to rules. Strips internal _claude_prompt and _skip_claude fields.
17
Rejoin Classification Paths
Merge (append)
Recombines the Claude-classified items and the rules-only items into a single stream. All items now have a final source_role, suggested_priority, and classification_source.
18
Trigger Registry Read
Code
Emits a single synthetic item to trigger the Google Sheets read that follows. Required because the Merge node output needs to be separated from the deduplication read: this node acts as the initiator for the second Sheets read.
19
Read Existing Registry
Google Sheets
Re-reads the full source_registry tab to get the current URL list for deduplication. A second read (vs. reusing the initial read) ensures the dedup check reflects any rows written by concurrent processes.
20
Match & Deduplicate
Code
Builds a URL lookup map from the existing registry, then compares each discovered candidate. Two outcomes: already exists → _action: update_metadata (only last_seen and last_checked updated). New URL → _action: insert_candidate (full row built with auto-generated source_id prefixed disc-{seed_id}-{slug}, status = candidate).
21
New or Existing?
IF
Routes by _action. TRUE (insert_candidate) → Strip Internal Fields → Write New Candidates. FALSE (update_metadata) → Update Safe Metadata.
22
Strip Internal Fields
Code
Removes the internal _action field before writing to Sheets: prevents a spurious column from appearing in the registry.
23
Write New Candidates
Google Sheets
Appends new candidate rows to source_registry using autoMapInputData. Status is always candidate. These rows are visible in Sheets immediately but are ignored by IPS until a human changes their status to active.
24
Update Safe Metadata
Google Sheets
For URLs already in the registry: updates only last_seen and last_checked, matched on url. No other fields are touched: this preserves any manual edits to status, priority, or notes made by the team.
warning_amber
First Run Not Yet Executed
As of Stage 5 deployment (2026-04-05), the first production discovery run has not yet been triggered. Validate by manually triggering the workflow in the n8n UI on a single seed before the first scheduled monthly run. Watch for: unexpected cross-product URLs passing the Reclassify & Filter node, section boundary enforcement working correctly, and Claude fallback behavior on unknown items.
tips_and_updates
Promoting Candidates to Active
After a discovery run, review newly written rows in the source_registry tab. Change status from candidate to active and set the correct priority (P1/P2/P3) to make a source eligible for IPS crawling. Sources with source_role = release_notes should generally be P1. SDK changelogs are P1. API reference pages are P2.
