Master Orchestrator

The conductor. Wakes up at 6:30 AM every weekday, decides which workflows to run based on the day, and chains all sub-workflows in sequence. The only workflow that runs on its own schedule — everything else is called by it.

info How It Works

The Orchestrator is the only workflow that runs on a schedule. Everything else is called by it. At startup, it computes three boolean flags: is_monday, is_tue_thu, and is_friday. These flags drive all downstream IF decisions.

Each sub-workflow is called with an executeWorkflow node — the Orchestrator pauses and waits for the sub-workflow to finish before continuing. This guarantees sequential execution: Market Watch always finishes before Competitor Intelligence starts, and Competitor Intelligence before the Newsletter.

A critical architectural rule: all IF nodes must reference $('Initialize Run').first().json — not $json. The $json variable reflects the most recent node's output, not the run context initialized at startup. Using $json in IF nodes caused real bugs during testing.

account_tree Node Breakdown
1
Daily Schedule 6:30 AM
scheduleTrigger
The alarm clock. Uses cron expression 30 6 * * 1-5 to fire at exactly 6:30 AM, Monday through Friday. Nothing runs unless this fires first. The trigger for the entire pipeline.
2
Initialize Run
Code
Creates a unique run_id for this execution (e.g., RUN-2026-03-31T06-30-00). Checks what day of the week it is. Sets boolean flags: is_monday, is_tue_thu, and is_friday. These flags control which downstream branches execute. All downstream IF nodes read from $('Initialize Run').first().json.
3
Log Run Start
Google Sheets
Writes the run's start record to the execution_log tab immediately — before any sub-workflow fires. This ensures that even if the run crashes halfway through, there is a record that it started. Columns written: run_id, date, workflow_name, started_at, status: "running".
4
Run Market Watch
executeWorkflow
Launches Market Watch workflow (ID: ppMzAEKShjv6L4EP) and waits for completion. Passes the run_id so Market Watch tags all its records to this run. continueOnFail: true prevents a crash in Market Watch from stopping the entire chain.
5
Market Watch Guard
Code
Guard node that emits a synthetic { status: "success" } item if Market Watch returned zero items. Without this, a Code node receiving 0 items never executes — the chain would break silently. This guard ensures downstream IF nodes always receive something to evaluate.
6
If Monday?
IF
Checks $('Initialize Run').first().json.is_monday. TRUE → Run Internal Product Specialist. FALSE → Skip IPS, proceed to Tue/Thu check. Mondays rebuild Ping's capability map for the rest of the week.
7
Run Internal Product Specialist
executeWorkflow
Launches the Internal Product Specialist workflow (ID: 63fbsmdUxNtnaFXG). Mondays only. Reads Ping's own documentation and rebuilds the internal_capability_map. continueOnFail: true — IPS failure does not block the rest of the run.
8
If Tue or Thu?
IF
Checks $('Initialize Run').first().json.is_tue_thu. TRUE → Run Competitor Intelligence. FALSE → Skip CI, proceed to Friday check.
9
Run Competitor Intelligence
executeWorkflow
Launches the Competitor Intelligence workflow (ID: mY5wIkPWlolzcUbn). Tuesdays and Thursdays only. Reads evidence from the last 3 days, compares against the capability map, and writes structured findings.
10
If Friday?
IF
Checks $('Initialize Run').first().json.is_friday. TRUE → Run Newsletter, then Memory & Audit. FALSE → Skip to final logging. Friday is the only day all 5 sub-workflows run.
11
Log Run Complete
Google Sheets
Updates the execution_log row opened at step 3. Fills in the ended_at timestamp and sets status: "success". The run is now bookended: when it started, when it ended, whether it succeeded. This is the final node in every successful run.
warning_amber
Critical: $json vs $('Initialize Run').first().json
All IF nodes must reference $('Initialize Run').first().json — not $json. The $json variable reflects the most recent node's output, which changes throughout the run. Using $json in IF nodes caused a real bug during testing where downstream conditions evaluated the wrong data.
