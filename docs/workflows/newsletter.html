Newsletter

Reads the week's structured findings, asks the AI model to write a competitive intelligence briefing, publishes it to Notion, and emails it every Friday morning.

Workflow IDmi4bUBXbiA1y5L8h
Triggered byMaster Orchestrator · Fridays
AI modelthe AI model: newsletter writing
Writes toNotion Weekly Newsletters · Gmail
Reads fromstructured_findings · error_log
info How It Works

The Newsletter is the final synthesis step of the week. It reads from structured_findings: the processed intelligence layer built by Competitor Intelligence on Tuesday and Thursday: and from error_log for the system health section.

The two data reads happen in parallel (Read This Week Findings + Read System Health Data), then merge. the AI model receives a structured prompt with a two-step novelty evaluation and a hard 500-word limit. Low-confidence items are labeled [LOW CONFIDENCE] in the output: never silently included.

The formatted HTML newsletter uses inline CSS so it renders correctly in Gmail. Dark navy header, orange accent headings, 600px card layout.

info
week_label Format
The week_label field formats the week as a Mon–Fri date range: e.g. April 7–11, 2026. This is used in the email header, Gmail subject line (PI Weekly Intel: April 7–11, 2026), and the Notion page title. Handles month-boundary weeks correctly (e.g. April 28 – May 2, 2026).
account_tree Node Breakdown
1
Called by Orchestrator
executeWorkflowTrigger
Entry point. Receives the run_id from the Orchestrator. Fridays only: after Competitor Intelligence has finished.
2
Read This Week Findings
Google Sheets
Reads all rows from structured_findings. Runs in parallel with node 3: both reads happen simultaneously before merging.
3
Read System Health Data
Google Sheets
Reads all rows from error_log. Used to generate the system health section of the newsletter. Runs in parallel with node 2.
4
Aggregate Findings
Code
Filters findings to the last 7 days using created_at >= cutoff (ISO timestamp). Excludes anything with status = "archived". This is a rolling 7-day window: not a month match: so each Friday newsletter only sees findings written that week.
5
Aggregate System Health
Code
Filters errors to the last 7 days. Counts them and bundles the list. A clean week = 0 errors in this count.
6
Merge All Data
Merge
Joins the two parallel tracks (findings data + error data) back together using combineBy: combineByPosition. Required to re-unite the two streams before the next Code node.
7
Combine Data
Code
Merges the two merged streams into one clean object: { findings, findings_count, week_label, errors, error_count }. This single object is passed to the Sonnet prompt.
8
Draft Newsletter (Sonnet)
HTTP Request → Anthropic
Sends all findings to the AI model with a two-step prompt. Step 1: evaluate each finding for novelty before writing (new source URL, meaningful content delta, new release note, new capability evidence, or materially changed interpretation). Standing observations and repeated prior-week conclusions are suppressed from the top section. Step 2: write using this structure: NEW THIS WEEK (novel findings only, each must answer "what changed?" and "why now?"), ONGOING WATCH (standing signals, max 2 bullets), RECOMMENDED ACTIONS (only if tied to new items), SYSTEM HEALTH (one line). Max 500 words. Items labeled [LOW CONFIDENCE] where appropriate. Quiet weeks produce an explicit "nothing material changed" note.
9
Format HTML Email
Code
Converts the AI Markdown output to inline-styled HTML. Dark navy header (#0a0f1e), orange <h2> accents, 600px card layout, all CSS inline for Gmail compatibility. Subject: PI Weekly Intel: [week_label].
10
Publish to Notion
HTTP Request → Notion API
Creates a new page in the Notion Weekly Newsletters database. Title: Weekly Intel: April 7–11, 2026 (date range format). Properties: week, findings_count, generated_at. Uses HTTP Request (not n8n Notion node: rich_text bug).
11
Send Gmail Newsletter
Gmail
Emails the full formatted HTML newsletter. emailType: html, appendAttribution: false. Uses the Gmail OAuth credential configured in n8n.
