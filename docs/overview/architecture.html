Architecture

Product Intelligence OS works like a team of specialized agents. One Master Orchestrator coordinates the schedule, while each agents handles a specific job and can be tested or run independently.

hub Orchestrator Pattern

The system uses a Master Orchestrator workflow as the single control point. It runs every weekday at 9:00 AM PT, checks the day of the week, and calls each sub-workflow in sequence using n8n's Execute Workflow node. The Orchestrator pauses and waits for each sub-workflow to finish before moving to the next step.

The Orchestrator never does analytical work itself, it only coordinates. It tracks each run in a Google Sheets execution_log tab: run start, run end, status. If any sub-workflow crashes, the Error Handler catches it and the Orchestrator is notified.

Google Sheets (config tab) ↓ Master Orchestrator (6:30 AM, Mon–Fri) ↓ Market Watch ──────────────────── runs every day ↓ Internal Product Specialist ────── Mondays only ↓ Competitor Intelligence ────────── Tue & Thu only ↓ Newsletter ─────────────────────── Fridays only ↓ Memory & Audit ─────────────────── Fridays only (after Newsletter) ↓ execution_log (Google Sheets) ← run bookended with start/end timestamps Error Handler ←── listens for crashes from ALL workflows above
extension Sub-Workflow Architecture

Every agent is its own n8n workflow, called by the Orchestrator via the Execute Workflow node. This design has three key advantages:

1
Independent Development
Each sub-workflow can be developed, tested, and debugged independently. You can trigger Market Watch manually without running the full pipeline. You can test the Newsletter without waiting for Competitor Intelligence to run first.
2
Easy Extension
Adding a new agent means creating a new workflow and registering it with the Orchestrator. No changes to existing workflows. The Orchestrator's IF node pattern makes it trivial to add a new day-of-week condition.
3
Failure Isolation
If the Competitor Intelligence agent fails, the Market Watch agent’s findings are still saved. If the Newsletter fails, the analysis data is still available for the next run. Each sub-workflow has continueOnFail: true in the Execute Workflow node, plus a guard Code node creates a placeholder item if the sub-workflow returns nothing.
error_outline Error Tracking

Every workflow in the system has its n8n Error Trigger configured to route to the PI: Error Handler workflow. When any workflow crashes, n8n automatically sends the error data to the Error Handler.

The Error Handler agent classifies each failure as critical or non-critical. Critical failures (Orchestrator, Newsletter, Error Handler itself) send an immediate Gmail alert. All failures are logged to the error_log tab in Google Sheets, a permanent audit trail of every problem.

info
Chain Resilience Pattern
Every executeWorkflow node has continueOnFail: true plus a guard Code node after it that emits a synthetic { status: "success" } item if the sub-workflow returned nothing. This prevents the Orchestrator chain from breaking silently when a sub-workflow produces zero output items.
