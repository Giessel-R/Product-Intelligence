Stage History

Each stage represents a validated upgrade to the intelligence pipeline. Stages are deployed incrementally — each one is tested and confirmed before the next begins.

1
Stage 1 — IPS Schema Strengthening
2026-03-29
Strengthened the internal_capability_map schema from 14 loose fields to 19 precise fields. Key additions: capability_area (renamed from lane), source_weight (deterministic, not Claude-assigned), support_maturity (controlled vocabulary: production_mature / documented / partial / unclear / sample_only), maturity_reason (required justification), capability_tag, freshness_status.

CI updated to read the new field names. First real competitive signal: Okta MCP Server, confidence 4, recommended_action: Draft Brief, review_flag: TRUE.
2
Stage 2 — Parser Safety Caps
2026-03-30
Added source-weighted extraction guidance and parser safety caps to IPS's Parse Capabilities Code node. Hard rules applied after Claude's response — regardless of what Claude returned:
  • sample_app → hard cap at sample_only, confidence ≤ 3
  • github_repo → cannot return production_mature without release/version signals
  • Vague evidence → capped at confidence 3
Validation: Exec 129 produced 34 rows, 0 parser caps fired (all sources had sufficient evidence quality). Stage 2 confirmed valid.
3
Stage 3 — Maturity-Tiered CI Analysis
2026-03-31
Upgraded Competitor Intelligence to produce maturity-aware analysis. Node 1 — Aggregate Ping Capabilities: Restructured output from flat array → tiered object per lane, with 5 explicit tier arrays always present (production_mature, documented, partial, unclear, sample_only) plus no_evidence: true flag.

Node 2 — Build Analysis Prompts: Added TIER DEFINITIONS block, REASONING ORDER (6 steps), CLAIM VOCABULARY table with anchored phrases for all tier-vs-tier combinations. unclear kept as its own bucket.

Validated finding (2026-03-31): Okta AI_AGENT_IDENTITY — gap_vs_ping = "possible gap — Ping's production claims backed only by press_release source." Press_release confidence downgrade fired from prompt guidance alone.
4
Stage 4 — Market Watch Relevance Gate
2026-03-31
Added a 2-node relevance gate to Market Watch between Has Page Changed? TRUE branch and Build Haiku Prompt. Gate prevents low-signal content from reaching Claude at all.

Score Relevance (Code node): Formula = base_score(source_type) + title_matches×2 + body_matches×1 (body capped at 5). Pass condition: score ≥ 3 AND keywords_matched ≥ 1. Base scores: changelog/release_notes/docs = 3, developer_portal = 2, github/blog = 1, homepage = 0.

Passes Relevance Gate? (IF node): Routes on relevance_pass === true. FALSE branch still updates the MD5 snapshot — just skips the Claude call.

Initial test (2026-03-31): 10 changed pages, all passed (all were docs pages). Drop behavior not yet validated — pending a run where blog/homepage/github sources also change.
